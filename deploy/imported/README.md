# 구즉 PM 게이트웨이 — 인증 대기

## 준비·검증 완료

- 서버 경로: /home/ubuntu/gujeuk-pm
- 공식 stable amd64 이미지를 digest로 고정했다.
- 실제 공식 entrypoint로 부팅하여 Hermes v0.23.2 CLI 실행을 확인했다.
- Docker Compose 구성, Python 구문, 셸 구문을 확인했다.
- 토큰 등록 도구 단위 테스트 9개 통과. 실제 Discord 인증은 사용자 입력 전이라 미검증이다.
- Discord browser 도구 비활성화 명령을 실제 실행했다.
- CPU 0.75, 메모리 1536MiB, swap 추가 사용 없음, PID 256 제한.
- 외부 공개 포트 없음. 별도 bridge 네트워크와 전용 data 디렉터리 사용.
- 운영 DB/서비스 폴더/Docker 소켓/개인 SSH 키/Notion 원본을 마운트하지 않았다.
- 폴더 700, 자격증명 파일 600. 기존 서비스 컨테이너 11개는 계속 실행 중이다.
- 공식 이미지를 받으면서 루트 여유는 약 4.7G(사용률 84%)가 되었다. 대량 수집 전 용량 확대·보존 정책이 필요하다.

## 사용자 실행

자신의 터미널에서:

`ssh -t ubuntu@3.37.79.125 'bash /home/ubuntu/gujeuk-pm/setup.sh'`

1. 숨김 입력으로 Discord 토큰 등록. bot ID·서버·보고 채널을 Discord REST에서 확인한 뒤 저장한다.
2. 제공자 로그인과 gpt-6.1-sol 모델 선택. 목록에 없거나 인증이 실패하면 다른 모델을 임의 선택하지 말고 중단한다.
3. 선택 완료 확인에 y를 입력하면 전용 게이트웨이를 시작한다.
4. 보고 채널에서 봇을 멘션하여 응답을 확인한다.

토큰·로그 전문·인증 코드를 대화에 붙이지 않는다.

## 현재 미완료

- 실제 Discord 토큰 검증과 메시지 왕복
- 모델 인증 및 실제 gpt-6.1-sol 호출
- 지속적인 Discord 채널 수집기
- GitHub 연결·태스크 대조
- Notion 인증·PM DB 생성·변경 동기화
- 로컬 초기 위키의 추가 보안 검토 및 서버 반입
- 앱 PM 탭

게이트웨이 연결만으로 모든 채널의 과거/새 메시지 수집이 자동 구현되지는 않는다.
개인 Notion 복제본은 팀 원본과 자동 동기화되지 않는다.
전용 bridge 네트워크는 호스트/인터넷으로의 egress 차단을 의미하지 않는다.
현재는 컨테이너 실행만 테스트했으며 모델 응답 성공으로 보고하지 않는다.

## 중단

인증 후 시작한 구즉 PM 게이트웨이만 멈추려면 서버에서:

`cd /home/ubuntu/gujeuk-pm && docker compose stop hermes`

기존 gujeuk-aws compose 프로젝트나 운영 볼륨을 조작하지 않는다.
