# 구즉 서버 채널 메시지 전송

## 범위

- 별도 대상 채널 허용 목록 없이 구즉 guild `1413450780068937790`의 메시지 가능 채널을 지원합니다.
- 다른 서버·DM은 거부합니다. 일반 팀원은 조회만, 실제 구즉 PM/법동 PM 역할 보유자만 준비/발송할 수 있습니다.
- 요청자에게 보이지 않는 채널에 봇을 대리자로 사용하지 못합니다. Discord 채널 권한을 변경하거나 관리자 권한을 부여하지 않습니다.
- 텍스트·공지·음성/스테이지의 텍스트 대화·활성 스레드·포럼 새 글을 지원합니다. 카테고리·첨부 전용 미디어는 제외합니다.
- 비공개 스레드는 요청자와 봇의 실제 참여를 확인합니다. 보관/잠긴 스레드를 자동으로 열지 않습니다.

## 사용

1. “공지 채널에 이 내용을 보내고 ⭕·❌ 반응도 달아줘”처럼 요청합니다.
2. 봇이 `channels`로 실제 대상을 확인하고 `prepare_message`로 초안을 준비합니다.
3. 봇이 대상·제목(포럼)·본문·알림 멘션·반응을 보여줍니다. 아직 게시되지 않습니다.
4. 같은 요청자가 같은 대화에 봇이 안내한 `발송 <초안ID>` 한 줄을 직접 입력합니다. 멘션을 덧붙이지 않습니다.
5. `send_message`가 현재 Discord 메시지 작성자/본문/대화/메시지 ID 및 실제 PM 역할을 확인한 후 게시하고 읽어 확인합니다.
6. 실제 게시 URL을 반환합니다. 반응 실패는 게시 성공과 별도로 안내합니다.

초안은 15분 뒤 만료합니다. 변경한 문구는 새 초안으로 다시 확인해야 합니다.
확인 문구를 도구 인자나 모델이 생성한 답으로 대신할 수 없습니다. 다른 사람이나 다른 대화에서 승인할 수도 없습니다.

## 멘션과 전달 결과

- 기본은 모든 알림 멘션 차단입니다. 준비 시 `mention_roles`/`mention_users`에 명시하고 본문에 있는 대상만 허용합니다.
- 역할 멘션은 해당 역할의 mentionable 또는 봇의 역할 멘션 권한을 확인합니다. everyone/here 알림은 지원하지 않습니다.
- Discord 전송 권한·기록 보기 및 요청 시 반응 추가 권한이 필요합니다. 부족한 권한은 거절하며 자동 변경하지 않습니다.
- 포럼 새 글은 title과 필요 시 tags가 필요합니다. 기존 포럼 글에는 해당 스레드 ID로 보냅니다.
- 동일 request_id는 같은 초안을 반환하며 다른 본문으로 재사용할 수 없습니다.
- SQLite의 원자적 예약으로 병렬 중복 발송을 막고, 일반 메시지는 Discord nonce/enforce_nonce도 사용합니다.
- POST/읽기 확인의 결과가 불명확하면 unknown으로 보존하고 재전송하지 않습니다. 새 초안을 만들어 자동 우회하지 말고 실제 게시 여부부터 확인해야 합니다.
- 발송 영수증은 반응 추가 전에 저장합니다. 반응 오류나 같은 요청 재시도는 메시지 POST를 반복하지 않습니다.
- Discord 역할/권한 확인과 실제 POST 사이에 플랫폼 전체를 잠글 수는 없습니다. 발송 시점에도 Discord가 봇 권한을 강제합니다.

## 운영·검증

- 영수증/초안은 private `pm-workspace/discord-outbox.db`에 저장합니다. 기존 정기 백업은 파일이 생긴 뒤 이를 추가로 SQLite backup/quick_check 합니다.
- `tests/test_discord_messaging.py`는 가짜 Discord REST와 실제 임시 SQLite로 확인·인가·중복·불확실한 결과·반응·포럼을 검증합니다. 실제 게시가 아닙니다.
- `scripts/verify_discord_outbox.py`는 배포된 플러그인 스키마와 실제 봇의 채널 권한을 GET 요청으로 검사합니다. 메시지/초안을 생성하지 않습니다.
- 실제 발송 종단 검증에는 사용자 승인된 실제 메시지가 필요합니다. 시스템 점검 목적으로 팀 채널에 임의 테스트 공지를 보내지 않습니다.
